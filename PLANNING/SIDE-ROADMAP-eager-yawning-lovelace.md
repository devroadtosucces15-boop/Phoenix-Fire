# Phoenix roadmap (final draft for approval)

## Context
The owner dictated six work items for Phoenix Fire and asked me to order them by quickest delivery and fewest dependencies, so later steps do not break earlier ones. Standing rules from the owner: when two versions of a feature exist, the latest wins; every button, notification and redirect must land on a current, correct page; no feature gets a second landing page; Phoenix branding carries through every output (CLAUDE.md rules, brand/leakcheck tests); finished work is verified, pushed and merged to main (memory notes).

Evidence comes from five read-only audits (source and git only; nothing was built or opened in a browser yet).

## Global order

1. **Item 3 backend: EA decoded columns.** First, and time-sensitive: EA serves only the last 10 matches per type, and Phoenix stores `evraw` for none of its 65 matches. Every match fetched before the fetcher keeps raw events is lost for decoding.
2. **Links (Phase A, B, D1, D5).** Small, independent, immediate user-visible fixes.
3. **Menu gaps and duplicates (Phase C).** Small.
4. **Item 4: Card Studio and `/avatarcard`.**
5. **Item 3 visuals:** match view, match center, box score, new derived stats.
6. **Item 5: Control Center CRM dashboard** (largest; backend, shell, dashboard, DJ bridge in parallel, permissions and sign-in last).
7. **Item 6: visual and performance enhancement pass** (after all else, after the owner supplies resources).
