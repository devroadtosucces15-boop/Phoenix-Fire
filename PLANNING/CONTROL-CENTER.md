# Control Center (2026-11-12)

One page on the site (`staff-controlcenter.html`, managers and owner) to switch, aim and restrict every output the bot and site produce.
The website and `/setup output` write the **same rows**; the Worker reads them at runtime from D1 (15 s cache), so no deploy is needed.

## Data model
- `output_controls (key PK, enabled, rules JSON, updated_at, updated_by)` (migration 0062). No row = on, default rules, the feature's own permission checks decide. A row that equals the default is deleted.
- Rules: `allow_roles, allow_members, deny_roles, deny_members, allow_levels, deny_levels, allow_channels, deny_channels, post_channels, min, reply, methods{site,dm,push}, windows[{days,from,to}]`. Deny wins over allow; blank = default.
- Keys: `slash:/name`, `comp:<folded custom id>`, `auto:*`, `job:<fn>`, `dm:notify:<type>`, `site:<flag>`.
- Every write goes through `saveControl()` (`bot/controlcenter.js`) and lands in `config_audit` (who, before, after, when).
- `notifications.on_site` (migration 0063): the site box per notification, independent of the DM.

## Panels (slicer switcher, replaces the panel in place, filter by app / type / on-off)
Site access (feature levels, merged), Bot commands, Buttons & menus, Automated posts, Scheduled, DMs & notifications, Organization (owner: channels/roles by purpose, merged), Audit log. Pickers can create a Discord channel or role.

## Registry rules
`bot/registry.gen.js` is generated by `studio.mjs registry` from COMMANDS, the studio captures, `notify.js` TYPES, `job()` calls in `worker.js` and `config.json` features (301 outputs today). `tests/controlcenter.test.mjs` fails if it is stale, if anything exists without an entry, if a poster module is not a registered source, or if a channel/role name or ID is hardcoded. README of bot-studio tells new outputs to register.

## Permissions
`controlcenter.manage` = manager and owner. Site access and Organization editing stay owner-only. The queue's pause/stop use `servertools.setup`.

## Notifications
Default ON for every type and method for everyone. Methods are independent checkboxes (Site, Discord DM, Push) plus an "All" box per type; old stored prefs migrate on read (`dm` = all, `site` = site only, `off` = none; announcements keep one box). Managers can switch a type off, remove a method, limit by member/level, or set time windows.

## Migration plan
Apply migrations 0062 and 0063 (additive). The old `bot_commands` blob is read once into rows and no longer written. Old prefs are translated on read, nothing rewritten.

## Anti-troll audit (Rush queue)
Closed: member Pause removed (managers/owners/admins only); idle hour auto-closes; join limit; failed/back-in-line keeps total time; Need a player is rate-limited and pings only the configured audience. Options left for the owner: per-member cooldown after Leave, auto-removal after N minutes without confirming, role-gating Join.

## Honest notes on timers
Discord's `<t:..:R>` text counts live on the client with no edits. "Time in the current state" and queue-open time are fixed timestamps rendered that way; the board itself is only re-posted on a button press or the 1-minute cron.
